# V0.1 首轮试玩记录

日期：2026-10-14。游戏/数值版本：0.1.0；存档结构版本：1。

这是一轮自动化操作试玩：Playwright通过真实界面分配人手、安排工程、领取事件、研究、读档；等待由浏览器时钟加速。经济、生产与离线计算均使用正式引擎。这些结果验证可完成性与数值节奏，不代表真人可理解性或长期平衡已经验证。

## 环境与路线

- 本机 Node.js 23.11.0、npm 11.3.0，Chromium 156.0.8078.4（Playwright 1.64.0）。
- 桌面：1440 × 1000；手机竖屏布局：390 × 844。另查320 × 700窄屏。
- 两个流程都从新存档开始，初始2名影子居民；完整流程得到2名回声居民。
- 保留一位发电工；早期在回收与维修间调配第二人。宿舍完成后，让回声居民先维修，再安排记录。
- 首次照明选择明灯；先建仓库再建信箱；研究工具规范、回声整理后修复旧站台。
- 连续查看与短段调整覆盖初期；后期预排三个项目并一次离开15分钟，自动完成站台、保留最后事件。

## 经营效果与等待

- 岗位调整实际改变工程进度；零维修工时费用不会预留，队首显示“未分配维修工”。
- 配置测试实测暗灯提高回收，明灯提高记忆；首次选择不扣零件，后续切换扣5零件。
- 两类居民、设施等级与研究倍率共同影响产出；供给不足与接近满仓时同比缩减投入和成果。
- 完成工程不会把最后一秒多余工程量送给下一项，下一项从后续秒开工。
- 信箱完工后记录员需要主动安排，返回报告说明当前目标；新居民也保持空闲，界面显示空闲人数。
- 末期记忆满仓，记录员停止消耗零件；人手可以改派。库存自然限制离线成果。
- 取消运行项目展示剩余费用、实际入库和容量溢出；返还不增加累计取得。

## 布局与修正

桌面三列与手机单列的完整流程通过；暗色、浅色和章节终点截图已检查，页面无横向溢出。键盘可切换主题、进入确认框并用Escape退出。

首轮浏览器流程发现队列数量进入“工务”按钮的辅助名称，已为导航设置稳定中文标签。存档文件选择控件也采用中文提示，避免依赖浏览器默认的英文按钮。

手机上岗位与事件位于主内容之后，需要纵向滚动；测试已实际完成全部主线操作。未来可缩短这段导航距离。真人阅读、手机触摸设备、其他浏览器与不同经营路线尚未试玩。

## 可复现证据

运行`npm run test:e2e`会在`test-results/`生成桌面/手机的`*-playtest.json`与初始、章节、浅色截图。JSON保留里程碑、资源账本、居民、事件和完整完工记录；测试结果目录是可重建产物，下一次运行会更新。
