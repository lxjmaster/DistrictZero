## 1. 方案结论与范围

建议在V0.4分所之前，先分三次交付补强前三章：

1. **V0.3.1「旧物与新用途」**：构件生产、可选预制施工、一条居民支线、维修台两种改装，以及跟随经营状态变化的街景。验证前期是否出现值得做的选择。固定首批已本地实现，体验目标仍需真人反馈。
2. **V0.3.2「街巷有了生活」**：委托板、外勤调查、居民回访、街区差异与更灵活的第二章达成方式。固定第二批已本地完成并通过功能验证，是否形成自主目标仍需真人反馈。
3. **V0.3.3「值得等待的列车」**：雨城与长站特产、生产模式、目标供货、货物空间预留与车辆改装。验证城际网络能否带来独特机会。

完整方案将常用库存从3种扩展到6种；以3位固定联系人、3条各4节点的支线、6处调查地点、6组各3阶段的委托、6种改装和可变化的街景连接这些物资。上述数量用于控制工作范围，体验改善以第17节验收为准。

以下内容继续留在原后续版本：分所与挑战城市、跨城历法、时间储备、公约组合、账号和跨设备同步。本文只为它们建立足够丰富的基础经营与内容接口。

## 3. 玩家体验与核心循环

新增循环围绕具体生活问题展开：

> 发现一件旧物或一项需要 → 决定材料和人手的用途 → 生产、调查或运输 → 完成一项改变 → 获得回信、知识或新机会 → 选择下一步。

主线、支线与日常生产共用库存和人手，玩家可以自行安排投入顺序。

| 使用时长 | 主要体验 | 支持方式 |
| --- | --- | --- |
| 约1分钟 | 看见成果，处理一个决定，安排下一件事 | 返回摘要、待办聚合、生产目标和现有模板 |
| 约5–10分钟 | 调整生产、比较投入、完成一段居民故事 | 投入预览、委托追踪、改装比较、调查准备 |
| 约20–30分钟 | 尝试一种发展重点，观察瓶颈变化 | 多个同时可见的可选目标、成本结构不同的改装 |
| 离开15分钟至24小时 | 按安排运作，保留重要选择 | 统一离线结算、数量目标、物资保留线、容量预留 |

早期体验的候选节奏如下。分钟数是观察窗口，解锁实际由游戏进度决定，不按现实时间强制弹出。表格描述三批完成后的整体体验；首批先验证前三行与既有主线，不显示后续功能的空入口。

| 观察窗口 | 目标体验 |
| --- | --- |
| 0–3分钟 | 保持原有路灯与两名夜工的经营取舍；第一盏灯归档后出现装配纸条和收音机线索 |
| 3–10分钟 | 能选择先扩建或试制构件；收音机有两种处理方式 |
| 10–20分钟 | 看到第一次人物回应和街景改变；可决定是否投资维修台改装 |
| 20–40分钟 | 主线、委托或调查形成不同投入方向，能够安排后离开 |
| 第二章 | 选择专业生产或街区协作；旧巷、信笺里具有自己的生活成果 |
| 第三章 | 决定本地生产什么、外城生产什么、运回哪些货物，以及如何使用特产 |

候选时长目标：不参与支线的首章仍以30–60分钟为调优区间；前三章主线暂以100–150分钟观察。支线带来的额外时间单独记录。不得通过统一拉长工时、增加必交材料来达到时长目标。

### 4.1 六种常用库存

| --- | --- | --- | --- | --- |
| 电量 | `energy` | 开局 | 发电 | 照明、生产、装配、运输、调查补给 |
| 零件 | `parts` | 开局 | 回收、长站常规生产 | 原有建设与维修、加工构件、委托、雨城供给 |

| 标准构件 | `component` | 第一盏灯归档 | 装配岗位、有限支线/调查奖励 | 改装、街区委托、部分调查处理 |

设全城仓库等级之和为W。原有三资源容量使用已发布规则。

| 资源 | 本城容量候选值 | 外城容量候选值 |

### 4.4 经济约束

- 新主线不统一追加三种新材料，新增物资首先支撑可选能力与内容。
- 同一物资至少连接两类用途，其中至少一类有明确的机会成本。
- 生产、运输、故事奖励和返还继续分别记账；进口不增加原有累计取得。
- 正常生产可以投入时间、人手和电量创造增值；禁止的是即时回兑套利、重复领奖和没有实际投入的产出。
- 调整经济时比较完整成本：原料、用电、人手时间、设施容量、运力时间和维护分摊。不能只看单份配方的物资数量。
- 委托和收藏均有明确的本批次终点，不靠每日重置和无限小额奖励延长内容。

## 5. 装配岗位与生产安排

### 5.1 岗位规则

新增`assemble`装配岗位，使用已有维修台。维修工和装配工共享本区维修台容量：

> 本区维修人数 + 装配人数 ≤ 维修台等级 + 1。

上述上限只适用于已建维修台；没有维修台时，两种岗位上限均为0。

两类居民都能装配，暂不增加居民类型专属倍率。维修台等级的现有效率加成适用于装配；R01仍只提高维修进度。两种岗位占用独立居民，装配不会同时产生工务进度。

装配采用连续生产：每名工人基础每秒产出0.020构件，消耗0.160零件、0.080电量，相当于8零件、4电量和50居民秒生产1构件；1居民秒表示1名居民工作1秒。使用现有0.001单位精度，供给或空间不足时产出与消耗同比缩减。

维修台效率提高处理速度，装配投入随处理量同步增加，保持每构件的零件配方比例。最终产出先按0.001单位量化，再据此计算消耗。配电亭按既有规则降低装配用电；照明、居民特性、记录研究与专业区不另外提高装配产出。第6节的单位成本均为不含配电亭的基准值。

装配独立于工务队列推进。主线施工与装配竞争人手、维修台岗位和原料，避免把所有新内容再次串进唯一工务队列。

### 5.2 目标与保留库存

- 初次启用装配时，推荐构件目标5、本城零件保留20、电量保留10；玩家可修改。解锁本身不自动分配人手。
- 库存达到目标或保留线时，装配工待命，不继续消耗材料；不自动改派到其他岗位。
- 多区装配共用全城构件目标与保留线，按现有稳定街区顺序分配本秒预算；不允许多个区分别越过保留线。
- 全城工作优先级增加装配。默认放在现有三类工作之后，玩家可调整。
- 库存目标与自动保留量使用0–1,000,000的有效数值，最多3位小数。目标高于容量时提示瓶颈、以容量为有效上限；保留量高于容量时提示自动任务将等待。不静默修改保存值。
- 界面展示“维修2＋装配1／维修台3岗位”，同时提供每秒投入、产出和达到目标的估时。
- 应用岗位模板前，一次检查维修与装配的共享岗位上限，以及外勤、外派占用的人手；全部满足才应用，否则保留原安排。

### 5.3 恢复办法

提供主动“拆回零件”：1构件换4零件，按整份执行，先检查输出空间；失败不扣构件。计入回收返还，不增加原有累计取得。即使使用节料改装，构件的零件投入也高于拆回所得。这个操作用于纠正过量装配，不提供自动循环。

没有构件不会阻断原有主线。装配只需要原有资源；不需要先拥有改装或特产。

## 6. 设施与车辆改装

改装采用“蓝图发现 → 制作一次 → 选择启用”的规则。每区维修台、每区信箱、全网车辆分别有1个改装位；同一位置只能启用一种方案。已制作的方案可在满足切换条件时免费切换，配方和效果不叠加。

制作属于一次性工务，完成一次并记录拥有状态。切换维修台、信箱改装从下一逻辑秒生效；车辆方案只在全网无在途/待卸货列车时切换，玩家可先暂停合同等待卸货。切换不重置工程、库存、线路状态或既有政策。

制作设施方案前要求本区已有对应设施；制作车辆方案前要求已有车队。制作成功不额外占地，装配也不新增基础建筑。

蓝图属于全城知识；制作所得方案属于对应街区或车队。制作完成不自动替换当前方案。拆除设施时保留该区已制作方案，重建后可再启用，不返还制作材料，也不能用拆建重复取得成果。被拆除的设施不继续提供改装效果。

| 改装ID | 位置 | 效果候选值 | 代价或取舍 |
| --- | --- | --- | --- |
| `mod:quickJig` 快速夹具 | 维修台 | 装配基础产出0.030构件/人/秒 | 每构件12零件、6电量，适合工期紧而原料充足 |
| `mod:thriftBench` 节料台面 | 维修台 | 装配基础产出0.015构件/人/秒 | 每构件6零件、3电量，适合原料紧而愿意等待 |
| `mod:voiceBox` 留声匣 | 信箱 | 记忆基础产出乘1.20 | 记录员基础零件消耗乘1.50，电量消耗维持基准 |
| `mod:dispatchBox` 投递匣 | 信箱 | 开放有数量上限的委托代办 | 本区记忆产出乘0.85，适合安排后离开 |
| `mod:freightRack` 强化货架 | 全网车辆 | 单车运量增加20 | 每次发车额外消耗2电量 |
| `mod:railGuard` 护轨挂架 | 全网车辆 | 每次发车磨损乘0.75，最终向上取整 | 使用原有运量，放弃强化货架的增运能力 |

候选制作费用：维修台方案各需2构件、8零件、10电量、4记忆、60工程点；信箱方案各需3构件、8记忆、10电量、90工程点；车辆方案各需4构件、2轨芯、20电量、120工程点。

蓝图均至少有两种有限获取途径，见第7、8、9节。相同蓝图再次发现时补充来源注释与对应回信，不额外发放数值奖励；已处理的来源不能重复领取。重复蓝图不会因记忆满仓阻碍委托或故事完成。

既有明灯/暗灯、专业区、研究和E12班次继续参与计算。实现时集中规定乘法与取整顺序，禁止分别取整或反复切换带来额外产出。

## 7. 固定联系人与三条居民支线

### 7.1 联系人的定位

首批固定联系人为“带收音机的住客”“两家人的邮差”“长站站务员”。联系人提供身份、回访和委托，不额外增加或占用可分配人口。人口生产仍按影子、回声类型计算，避免把同一人重复计入。

每人有一个小档案：称呼、第一次见面的地点、目前的事、已知细节、玩家做过的选择、最新回信。具体姓名可以通过故事逐步确认，不设置通用好感度货币。

所有重要选择停留在待处理列表。资源奖励需要空间时保留整个结算包；人物事实、后续开放和奖励在确认领取时一次性应用，不发生只发一半的状态。

每个支线节点还要求前一节点已确认。即使玩家已完成较后章节，也不跳过未决选择；只提前满足节点的章节条件。

### 7.2 L01：收音机里住着谁

| 节点 | 开放条件 | 内容、选择与结果 |

### 11.2 装车与合同

将固定1/2份界面扩展为明确货单：选择本路线允许的整份货包数量，合计不能超过单车容量。每种货包1份的资源数量直接显示；数量上限由容量计算，并设合法整数范围1–32。允许同车装载同一来源的常规产物和特产；不得发运不存在的库存。

- 去程货包：对应选定配方的一份补给。
- 雨城回程货包：12记忆一包、2胶片一包，可混装。
- 长站回程货包：32零件一包、2轨芯一包，可混装。
- 未选货包为0，至少一种货物大于0。原来1/2份操作映射为相同的普通货单。
- 每次运输保留原有时长、耗电、线路磨损与人手要求，改装在发车前计算；发车快照（snapshot，即出发时固定的货物、时长与费用）不随后续设置变化。

自动合同增加两个概念：本城产物目标、外城补给缓冲。新合同默认按所选模式补给2个生产周期；常规资源目标由玩家确定，特产推荐目标6。每条线的两种产物分别设置目标，默认优先当前模式产物；另一种仅从现有外城库存顺带取回，不触发自动换配方。保留原有本城最低库存与线路优先级。

合同继续支持最多3位小数的保留量，以十进制字符串精确转换。暂停只使用已保存配置并停用合同，不提交或校验未保存草稿；保存与重新启用才检查新输入。

确定性调度顺序：

1. 已在途货物继续运输与卸货。
2. 若本城未达产物目标、来源备齐且可预留容量，优先取回；按目标缺口、整包数量和车容确定货单。最后一包可以超过目标，不能超过容量。
3. 否则，只有当前模式产物在本城仍有需求时，才按所选配方检查外城是否不足2周期补给；不足则在本城保留线内送一车，不能超过目标城市空间。
4. 已满足目标时正常待命；不因满仓而反复发车。所选模式、保留量或目标阻止发车时展示具体原因。

每份合同只自动供给玩家选择的一种生产模式，不在后台自行切换城市模式或代选故事路线。混装比例由玩家保存；自动取货按货单顺序使用运量，避免相互等待整车凑齐。简单模板提供“补本城原料”“取城市特产”，高级字段按需展开。

目标物资被消费后，合同可恢复发车。特产仍有库存时，玩家可切回常规模式继续生产；保留库存和已在途货物不随切换丢弃。

### 11.3 在途容量预留

新发出的运输在目的地预留整车货物空间，适用于两端：

> 目的地当前库存 + 已持有的在途预留 + 本次货物 ≤ 目的地容量。

目的地产出、奖励领取、新发车和缩减仓储都检查预留。到货时原子释放本车预留并增加同量库存，货物仍然只属于列车，尚未提前入库。

界面例如展示“零件库存220／400，另有64在途预留”。满目标属于正常待命；真实缺料、等待维护与存量旧车待卸货分别提示。

旧存档中已在途、且目的地可能已满的车维持旧版等待卸货语义，不强行清空库存或伪造预留；详见第15节。新预留不会覆盖这些旧货物。

### 11.4 第三章达成与档案复原

P08、P09、P10继续引导玩家至少体验两城及一次回程。P11建议改为：P10完成、两地均有过一次回程，至少一条供货合同目标大于0、已启用、有外派与有效线路，且能够响应需求或目标已满足。已发车的运输按支付完成的运行费用判断，不因途中本城电量下降而失效。没有新增累计等待时间；无需同时启用两个合同或为第二次到货刻意暂停本地产出。

E12稳班／快班的已选政策继续有效，分别与车辆两种方案组合。两条路线的当前试玩时间只差30秒，不能据此判定政策强弱；需要比较阶段瓶颈与维护、人手、运力成本。

档案复原作为有限收藏项目，解锁来自F05修棚或CM05第1阶段，任一路径均可。三份分别完成一次，各给出可读结论、地点关联和补充文本，不兑换成通用研究点，也不隐藏基本操作信息：

| 档案 | 候选费用 | 结果 |
| --- | --- | --- |
| 没有寄件人的雨声 | 2胶片、4记忆 | 解释一段雨声的来源，补充F05场景与档案 |
| 第0节的交班 | 1胶片、1轨芯、4记忆 | 对照运单与旧接头，补充F06站务记录 |
| 空白地址的另一面 | 2胶片、1构件、6记忆 | 关联第0街区与窗口来信，在街景标注已知联系 |

收藏回报与生产能力回报分开说明；收藏完成数不作为两条策略路线成立的证据。费用须与CM05、车辆改装争夺同批特产。

## 12. 街景与视觉反馈

### 12.1 表现方式

采用轻量矢量图形（SVG）、样式（CSS）与文字表现街景，继续适配桌面和手机。街景表现当前经营事实，布局不参与寻路或设施相邻加成；先避免把展示地图扩成另一套建设规则。

街景节点可点击查看地点与对应操作。每个主要节点至少区分未开放、可修复、施工、可用、暂停或有事项；基础设施表现等级变化，公共设备表现供电与状态。

| 成果或状态 | 可见反馈 |
| --- | --- |
| P01路灯完成 | 灯亮，灯下出现可辨认的两名夜工轮廓 |
| 宿舍建设与入住 | 新窗户、亮灯窗口和住客物件；回收与记录安排有不同细节 |
| 收音机拆解／修复 | 维修台工具盒／窗口收音机，归档可追溯来源 |
| 信箱建成或有来信 | 信箱及信件标记；点击进入对应事项 |
| 旧巷开放与CM02完成 | 新巷道、晾衣绳、支架与邻里回信标记 |
| 信笺里与E07选择 | 两家共灯或两行门牌，对应窗口变化 |
| 公共设施有效／耗尽 | 配电亭与事务所运行状态，明确区别于建筑消失 |
| P03、P08与运输 | 站牌、车厢和列车位置；车辆按真实剩余时长表现 |
| CM04、CM05、CM06成果 | 长椅、听雨间、修车棚；可点击看变化缘由 |

动画用于确认状态，限制循环闪烁；关闭动画或系统减少动态效果时使用静态位置。状态同时通过文字、形状与图标表达，不只依赖颜色。

### 12.2 信息层级

- 顶部先给当前目标、当前可做选择与街景；长期档案和历史记录收拢。
- 目标压缩到街景头部，合并区域候选高度为桌面约240px、手机约180px，避免在现有大目标卡之上再堆一整块展示区。
- 资源按基础、加工、城际分组展开；只展示已发现资源，点击可看来源、投入、净变化、目标及预留。
- 已完成主线默认收起，满级设施压缩为摘要；可操作内容获得主要空间。
- 目标分为一个主线目标和至多两个玩家追踪目标，避免所有系统同时抢注意力。
- 等待提示聚合相同原因，指出会受影响的工作与可行解决方法；“按目标待命”作为正常状态。

### 12.3 页面与设备

桌面：左侧资源和人手；中间街景、当前行动与内容；右侧待处理事项、返回摘要和关键提醒。

手机：资源简栏、街景/当前目标、当前页面依次排列；常驻入口可打开人手安排面板或待办，不再要求滚过全部设施才能调人。触控目标至少44px，长表单逐步展开。

主导航建议为“街区、工务、事项、夜网、档案”，设置放在页头。街区选择和夜城概览纳入街景，事项整合居民来信、委托与调查，夜网按章节开放。第1批先调整街区首页与手机安排入口，第2批再整合导航，避免一次重写全部页面。

### 12.4 返回报告

报告先展示最多3项值得注意的成果，例如“工具盒放在维修台旁”“旧巷有人替邻居留了路”“雨城首批胶片已到站”；随后列出待选事项和下一步安排，详细账本可展开。

报告区分实际入库、待领包、在途货物与容量预留。街景变化来源于实际状态和一次性成果；装饰动画或经过的夜数不能代替真实经营成果。

## 13. 自动化、离线与恢复边界

| 场景 | 规则 |
| --- | --- |
| 离开15分钟 | 当前工务、装配目标、一次调查和既定合同继续；新选择等待 |
| 离开1小时 | 生产遵守目标/保留线；自动巡检继续，委托只按已确认的代办清单交付 |
| 离开24小时及7天 | 仍按同一逻辑结算；目标已满正常待命，不扩增未确认任务或重复奖励 |
| 满仓 | 实际产出与投入同比减少；未领取奖励保留，新运输检查预留 |
| 调查返程时家中已满 | 居民正常返回，结果保存在待领包；外勤位释放 |
| 原料耗尽 | 工作暂停并标出原因；原有发电、回收可恢复基础供给 |
| 改装导致投入上升 | 界面预览，允许切回普通方案；不自动扣取超过实际产出的原料 |
| 线路耗尽 | 停止新发车，既有运输继续；维护使用现有工务队列 |
| 未处理故事很多 | 汇总待办；同地点不重复出发，达到调查结果上限后停止新增调查 |

自动化采用明确数量目标与保留量，不读取现实“每天几点上线”。重要故事不设置自动替选。人口增长、外派、外勤、岗位和迁居共同遵守人手与床位约束。

## 15. 技术落地与旧存档

### 15.1 最小模型扩展

沿用TypeScript、React、Vite、CSS、Vitest、Playwright和现有纯模拟边界。新增模块只服务当前批次，建议按职责从现有大文件中提取，不进行全仓重构。

| 模型 | 新内容 |
| --- | --- |
| 资源定义与账本 | 构件、胶片、轨芯；单位、容量、来源与产出分类 |
| 岗位和模板 | `assemble`、维修台共享上限、四类非发电工作优先级、目标与保留线 |
| 改装 | 每区已制作方案、当前启用方案、全网车辆方案 |
| 联系人与故事 | 稳定链路/节点ID、待处理状态、首选分支、已确认成果 |
| 委托 | 6组各阶段状态、展示顺序、追踪与有限代办清单 |
| 调查 | 来源街区与居民类型、地点、预留补给、时长、进度、待领包 |
| 城市配方与合同 | 已选模式、产物目标、补给缓冲、货包顺序与数量 |
| 运输 | 发车时的货物/时长/费用快照、是否持有目的地容量预留 |
| 章节达成 | 从当前状态推导供给/网络能力，记录有限协作成果与旧前置兼容标记；不增加等待计时 |
| 街景 | 由设施与成果推导展示；只存无法从现状恢复的历史分支 |

人手占用统一计算：本地五类岗位＋本区来源的外派人数＋外勤人数不超过本区同类人口。修改模板、迁居、拆宿舍和召回均使用同一校验来源。

容量预留由持有预留的运单推导，不另存一份可独立漂移的总数。运输途中变更政策、改装、配方、货单不修改既有快照。

### 15.2 时间、记账与动作

新增机制继续使用同一逻辑秒、定点数（fixed-point，内部1000表示1单位）及动作串行化。装配参与现有供给分配与同秒受容量限制的补产预算，不获得第二份产能。外勤按经过时间推进；每秒仅在边界产生一次完成结果。

建议逻辑顺序：时钟与自动维护 → 发电、照明、公共设施 → 优先级中的生产/维修/装配 → 同秒容量补充 → 人口与工务完成 → 已有运输到货、城市配方、合同调度 → 外勤完成 → 已确认委托代办 → 新事件与结果汇总。新解锁的生产或自动任务从下一秒开始，不能在同秒递归产生无限动作。

现有账本的`reserved`继续表示工程预留；装配投入计入`operating`。增加`fieldReserved`和`fulfillment`，分别表示外勤出发预留、委托/可选内容的实际支付；召回与取消使用返还分类。详细报告给出这些来源，不能把外勤或委托支付混写成工程成本。

本城库存等式扩展为：

> 期末 = 期初 + 生产 + 已领资源奖励 + 实际返还 + 运回 − 运行消耗 − 工程预留 − 外勤预留 − 委托等支付 − 发出。

外勤预留从库存扣出后，处于该行动的持有状态；完成消耗或召回返还都不能再次扣同一笔库存。待领包、在途货物、库存和行动持有款分别验证。容量预留不是物资，不出现在物资收入中。

每个事件节点配置：稳定ID、前置、首选分支、明确费用、一次性成果、奖励包、后续节点和至少一项可感知反馈。台词只陈述已经发生或确实将由本次确认产生的事实。

文案保持安静、古怪、具体：围绕门牌、灯、工具、窗、信与列车写生活变化。内容给出可理解的经营原因，避免把所有居民都写成发布任务和发奖的接口。

### 17.2 真人试玩设计

第1批先找5–8位未参与开发的试玩者，分别覆盖桌面、手机与两种使用习惯：持续操作和安排后离开。这个样本用于发现问题，不估算留存率或宣称统计显著。

第一段从新档开始20–30分钟，尽量让玩家自己理解；第二段安排离开15分钟再返回。第2、3批另用真实章节存档测试中后期，避免所有反馈都被前期学习消耗。

记录内容：

- 玩家在哪一刻有两个想做的目标，为什么先做其中一个。
- 是否知道装配消耗什么、什么情况下该用快速或节料方案。
- 新资源有多少实际去处；是否只为下一个主线门槛积攒。
- 第一次无事可做或不知道该做什么的时点；区分主动离开放置和被迫盯条。
- 重复撤人、加人、腾仓、滚动找控件的次数与原因。
- 返回时先注意到什么，能否解释停止原因、说出下一步。
- 能否记住一位联系人、一个自己的决定和一处因此发生的变化。

### 17.3 体验验收标准

以下是待验证标准，不是现有测试结果：

1. 首批至少80%的参试者能在不提示的情况下说明构件的两种用途，解释快速/节料的一项真实代价；5–8人的小样本只用于初筛，完整记录保留逐人事实。
2. 首30分钟至少出现两类由玩家自己解释理由的可选投入；单纯领取、归档和反复加减人数不计入。
3. 玩家能够在返回后找到未决事项，指出一项实际世界变化及一个可执行安排。
4. 两种第二章、两种第三章安排均有完整路线证据；若一条在多数相关指标上被另一条全面支配，修改成本或回报，不只修描述。
5. 与相同目标、相近习惯的V0.3路线对照，非自愿的重复腾仓与翻找操作减少；主动生产规划不按“操作越少越好”评价。
6. 已掌握操作的玩家若出现超过约5分钟、且本想继续玩却只有盯进度条的区间，逐段查明原因并修复内容空档；玩家主动选择离开放置不属于失败。

首批真人反馈是后续批次范围与数值调整的依据。若联系人无人记住、构件只成为新门槛或街景变化难以辨认，应先修复对应问题，再增加第二批内容量。
