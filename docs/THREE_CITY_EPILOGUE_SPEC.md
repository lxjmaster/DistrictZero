固定日期：2026-10-26；实现验收日期：2026-10-27。状态：**V0.6.1已在本地实现并验证，尚未提交、推送或发布。** 本地为数值0.6.1 / 存档结构10，线上仍为V0.6.0 / 结构9，之前照明显示修订继续保留。以下固定设计与费用不变，T01–T10证据见[验证记录](VERIFICATION.md)，实际双端路线与费用见[试玩记录](PLAYTEST.md)。公开发布另按用户指令执行。

## 1. 范围决定与证据

将[三地联修候选](JOINT_GOALS_PROPOSAL.md)缩为一次性叙事档案任务，复用现有档案复原动作与收藏入口。它是六章后的可选尾声，不是第七章，也不作为解决后期长期经营目标不足的方案。

原候选的两部分工程没有不同的经营效果，又共用唯一工务队首。在材料、供电和人手均足够且无其他工务时，先修已到材料的一部分会提前或保持全部完工时间；“等齐再修”只推迟进度，并未形成费用或收益补偿。已有其他工程时当然可以权衡队列占用，但这属于原有工务规则，不能据此声称新增了策略机制。

使用真实章末的1.38工程点/秒作**足额施工纸面预算**，以两项各180工程点示例（每项131秒，示例随后弃用），轮内120秒开始、每城两包时：

| 物流与施工安排 | 雨城 / 长站材料到家 | 第一部分完成 | 全部完成 |
| --- | --- | ---: | ---: |
| 普通生产，先到先修 | 300 / 420秒 | 431秒 | 562秒 |
| 普通生产，等齐后先雨城 | 300 / 420秒 | 551秒 | 682秒 |
| 仅长站历法，先到先修 | 300 / 360秒 | 431秒 | 562秒 |
| 仅长站历法，等齐后先雨城 | 300 / 360秒 | 491秒 | 622秒 |

历法在物流子流程省下的60秒未缩短先到先修的总完工时间。其他工程量、人手、库存和窗口可能有其他结果；该例足以否定“物流更快必然使整个候选更快”，不能用来证明所有策略等价。

本次对原40组物流结果计算了40组条件排程预算，以及20组单包档案材料预算。没有向正式状态注入新工程、费用或完成标记；不声称执行了新目标。历史结果保留在`test-results/joint-goal-analysis/budget.json`。复跑使用当前源码并写入独立的新目录，其版本和摘要可能不同于历史结果；脚本依次核对输入及源码摘要。使用Node.js 22，从项目根目录执行：

```sh
analysis_run="test-results/analysis-run-$(date +%Y%m%d-%H%M%S)-$$"
npm run analyze:progression -- "$analysis_run"
node scripts/analyze-joint-goal.mjs "$analysis_run"
node scripts/budget-joint-goal.mjs "$analysis_run"
```

首步要求指定的目录尚不存在；也可省略参数，由脚本创建并打印唯一目录，再将该路径传给后两步。结果分别位于该目录的`progression-analysis/`和`joint-goal-analysis/`。重复执行时请创建新目录；脚本不会覆盖已有的同名结果。

因此去掉两项施工及两包投入，不改配方、历法窗口或公约费率来制造新用处。保留三地共同署名这一叙事结果。

## 3. 材料路径与直接预算

### 普通生产路线

既有无特产章末样本中，每城发一包原料并取回一包特产，共4趟单程；两次模式设置、两次去程、两次回程，共6次正式引擎动作。规格固定时，四个已测轮内起点均在360秒得到全部材料；当时第7次A04动作尚未实现。2026-10-27已从真实章末在正式引擎和桌面/320px界面完成普通路线：360模拟秒、6次物流动作加1次实际A04交接，共7次引擎动作。**360秒不含阅读、思考和界面操作；实际click事件双端各15次（含导航和取消复验），不等于引擎动作数。**

| 环节 | 电量 | 零件 | 记忆 | 构件 | 特产流向 |
| --- | ---: | ---: | ---: | ---: | --- |
| 一包雨城原料 | 10 | 12 | 0 | 0 | 外城生产2胶片，实车运回 |
| 一包长站原料 | 12 | 0 | 6 | 0 | 外城生产2轨芯，实车运回 |
| 四次基础发车 | 20 | 0 | 0 | 0 | 雨城2×4电、长站2×6电 |
| A04直接交接 | 0 | 0 | 4 | 1 | 消耗已到账2胶片＋2轨芯 |
| **上游原料＋运费＋交接基础投入** | **42** | **12** | **10** | **1** | 两种特产是中间产物，不再折算加收第二遍原料 |

这不是全城净成本：未计原有岗位与派驻的人手机会成本、正常照明/生产、公设维护、构件此前制造费用，以及因其他车辆改装、快班、磨损、仓库或公约而发生的实际差异。6次物流动作来自有现成人手、双车和足够容量的同一真实章末起点，不是所有存档的固定操作数或最短路线。

### 既有库存与工具

- 有足够旧城库存时，可以直接手动交接，不要求接取后新生产、不查“本次进口量”、不收两次费。A04无施工，不要求新增维修工或撤下原岗位。
- 尚未到账的在途货物、外城库存、待领取奖励以及被其他系统预留/持有的物资不能当作可交接库存。沿用正式可用库存与守恒规则；不转移或释放其他系统的承诺。
- 历法、公约、合同、车辆改装完全可选。已测20组单包物流中，没有历法方案比普通路线的360秒更快；单地历法另耗60秒储时、1次校准、4电＋1记忆，双地翻倍，旧储时原捕获投入仍保留其历史成本。任务不要求玩家为此启用工具。
- 已有合同可以继续；任务不自动改目标、模式、缓冲、保留线或排程。若玩家只想做这一份档案，可在原入口自行暂停不再需要的安排；暂停不撤销在途运单，也不删除已备料单。
- 交接后无持续投入。可停产停供、暂停储时/历法/公约并永久保留档案；既有安排不因交接自动停止或免除费用。

## 4. 引擎、界面与账本接入

本节为固定实现要求，现已落地并按T01–T10验证；精确执行范围与限制见第7节。

1. **内容配置**：在`journey.ts`扩展A04与显式费用；档案标识类型扩展为A01–A04。原A01–A03名称、费用、前置和文本保持原规则。
2. **逐项开放判断**：A04用自身前置，原三档仍用原可选委托/外勤条件。引擎、显示、缺料反馈和存档校验共用逐项判断，不能把“任一档案开放”等同于“四项都开放”。不放宽A01–A03前置来迁就A04。
3. **手动原子交接**：检查标识、前置、未完成、整份可用费用；失败保持原状态。成功一次扣款、一次记录`fulfillment`和A04、一次历史提示。交接不推进模拟时钟、不产出资源、不更新`earned`、进口、工务或公约证明。
4. **收藏呈现**：复用现有收藏页；达到前置的A04独立可见，即使前三档尚未开放。缺料显示完整费用、可用数量和停因；交接按钮保持明确费用说明。完成后永久显示完整文字和地点，不再显示付款按钮。320px可读，键盘可到达，忙于结算或非写入标签时沿用既有禁用规则。
5. **有限用途**：更新`remainingSpecialtyUses`的固定数量/分组假设，A04开放且未完成时列为一项有限用途；不因旧三档全完成就漏掉A04，不因A04已完成就隐藏未完成的旧档。尚未开放的尾声不提前暴露为当前待办。
6. **目标与报告**：不延长六章主线，不替换当前章末主目标；A04在收藏页作为可选尾声。返回报告按实际`fulfillment`差值显示支出；A04不混入工程完工、事件奖励或进口数量。原历史提示可记录一次收藏，避免再造档案专用收入账本或完成计数。
