# 六章连续推进与后期策略分析

日期：2026-10-25。本篇记录当时的本地分析与照明费用显示修订；该修订已于2026-10-27随V0.6.1公开发布，当前公开版本为数值0.6.1 / 结构10。

## 1. 方法与覆盖

通过`npm run analyze:progression`调用当前正式引擎，从`createGame(0)`建立唯一新档，连续完成P01–P19、两处分所的六项工程、必要来信、两地真实回程和跨轮历法加工。没有导入历史章末档，没有填充库存、人口、完成标记或免费成果。工程与生产使用原配置，等待按10秒采样；后期工程对照按1秒观察完成。

每次动作和推进均检查状态约束，全部检查点及21个对照终点均验证编码/解码后的完整状态相等。脚本记录Git提交、脚本与`src/game/*.ts`摘要、Node版本、完整动作、等待原因及账本。运行环境为Node.js22.23.2。

这是一条预先规划的**引擎路线**，不是新玩家发现过程、浏览器点击计数、最快路线或真人等待体验。已有各章桌面/手机界面证据继续按原记录引用；本轮不声称重跑所有界面路线。委托、外勤、车辆、档案等可选扩充没有全部重做，仍沿用原验收；本轮选择拆解收音机、共灯、稳班、两图本地值守与零追加支援。

输出位于`test-results/progression-analysis/`：

- `route.json`：完整连续路线、检查点、动作与等待。
- `strategies.json`：七种公约选择在三个工作负载中的21组对照。
- `chapter-1.json`至`chapter-6.json`：各章终点；另有两图与策略起点。

这些是当时的历史JSON，墙钟元数据保持分析原点0；**不能直接作为真人试玩导入档**。现在执行`npm run analyze:progression`会创建并打印新的`test-results/analysis-run-*`目录，不覆盖历史结果；使用当前源码复跑可能得到不同版本与摘要。后续物流和预算分析需使用同一个运行目录，具体命令见[尾声规格](THREE_CITY_EPILOGUE_SPEC.md)。现有[试玩入口](PLAYTEST_START.md)仍使用来源明确的正式路线导出。

### 可观察的交接成本

1. **生产提高后，容量成为下一阶段的条件。** E06/E08/E09的整份奖励需要空间；本路线先让后续工程实际预留费用再领取。第三章雨城回程前真实升级仓库；长站回程前停回收并升级发电机以腾出零件空间。没有丢弃奖励、强行卸货或补造容量。这是当前规则的经营约束，不据此判为故障或直接扩大仓库。
2. **分所段的岗位切换最集中。** 83次动作中52次是本地岗位增减；使用两人零追加支援，需要在回收、记录、装配、维修间切换。它证明此路线操作集中，不能直接推定玩家厌烦。增派人手和有限支援已有其他路线证据；本轮不额外增加自动轮岗。
3. **历法的主要等待可提前安排。** 雨城与长站等待重叠窗口分别累计480/390秒；期间旧城继续生产。两项加工都真实跨轮，消费储时与校准，产物留在外城，未当作已运回旧城的收益。
4. **后期基础库存被本路线的产能填满。** 第四至六章终点均为500电量、550零件、120记忆和12构件。主线费用能被持续生产补回；章末净库存不变不能证明系统免费或选择相同。

本路线中较长的等待包括首章P03累计980秒、分所记忆510秒和构件400秒、历法窗口870秒。各数值可能含备料与施工，不能统称“无事可做”；完整等待原因保存在原始输出中。

## 3. 后期策略对照

每个工作负载均从同一个真实路线检查点分支，先免费暂停旧约，再对非空组合支付一次相同调整费。对照包含暂停、三种单约及全部三种双约。不把电量、零件、记忆假定为等价货币。

### 3.1 同一真实工程P19

本路线保留一名维修工、一名装配工及实际供电；P19的费用、工程量、岗位与预制选择相同。各方案均付费生效且无欠费。

| 公约 | 完工秒数 | 相对暂停 | 公约直接费用：电量 / 零件 / 记忆 |
| --- | ---: | ---: | --- |
| 暂停 | 435 | 基准 | 0 / 0 / 0 |
| 封存 | 580 | 多145秒 | 17.6 / 4 / 7.8 |
| 续建 | 348 | 少87秒 | 23.4 / 10.96 / 2 |
| 并存 | 435 | 相同 | 6 / 12.7 / 6.35 |
| 封存＋续建 | 464 | 多29秒 | 38.48 / 13.28 / 6.64 |
| 封存＋并存 | 580 | 多145秒 | 17.6 / 15.6 / 13.6 |
| 续建＋并存 | 348 | 少87秒 | 23.4 / 17.92 / 5.48 |

直接费用包含调整与维护，不含共同工程费用、正常岗位消耗，也不扣除照明/运费节省。完工区间不同，因此不能把两行总生产相减称为同时间产能差。

**结论：**续建适用于愿意付费换提前完工的情况。本样本缩短20%完工时间；封存＋续建的施工倍率为93.75%，双约不会自动更快。并存在没有发车的工程区间没有运费收益，但仍有费用与回收折减。

### 3.2 相同六趟雨城运输

从同一P19待建状态出发，统一安排P19以实际腾出回程空间，并撤下记录员。按相同顺序完成三次补给和三次取货，共721秒；每组均真实运回36记忆、发出60零件，无货物丢失或滞留。初始外城库存也完全相同。

- 暂停时六次运费共24电量；含并存时共19.2电量，实际节省4.8电量。
- 单独并存的调整费为6电量、4零件、2记忆；721秒维护另付14.42零件、7.21记忆。
- 封存、续建同时作用于旧城照明、工务和生产；完整账本另列，不能只比较运费推断整个方案的净收益。

**结论：**本例中，“运费八折”不能覆盖一次启用的电量调整费，另外还要支付两类维护资源。是否值得启用取决于发车频率、运量、原有组合和资源瓶颈，不能仅按八折判断。没有据此修改并存数值。

### 3.3 章末饱和库存，空队列、停合同，15分钟

七种选择终点库存均与起点相同，因为在岗生产补回了消耗。账本仍记录真实投入：

- 单独续建：无新增工程收益，仍付45电量、18零件维护，以及6电量、4零件、2记忆调整费。
- 单独并存：无发车收益，仍付18零件、9记忆维护，以及同一调整费。
- 单独封存：实际照明少付54电量；公约维护18电量、9记忆，另付调整费。补回这些材料也会占用普通生产；照明节省不等于全城净收益。

**结论：**达成章节证明后可以按实际工作暂停公约。证明保留、免费暂停已有明确入口；本轮不加入自动选约、日常任务或无来源奖励。

## 5. 下一批内容方向

**建议优先探索现有系统的有限后期目标。** 原因是本路线P19后已出现基础库存饱和，续建/并存是否继续运行取决于还有没有真实工程与运输工作。该结论仅支持做设计候选，尚不能证明所有玩家都缺目标或需要更多内容。

先比较两个候选：

| 候选 | 可以带来的价值 | 新增负担与取舍 |
| --- | --- | --- |
| 现有三地的有限联合工程 | 让运输、当地加工、工务、公约在同一明确目标下配合；复用现有资源与地点 | 必须说明真实取舍、有限终点、投入来源，避免只是加大费用重复等库存 |
| 无门城等新规则城市 | 新的探索与世界观发现 | 新地图、规则解释、来源守恒、迁移与操作面更多，当前缺少优于前者的具体玩法证明 |

下一交付应是范围有限的候选设计与比较：玩家目标、涉及系统、实际选择、预计操作量、完成后可停的条件，以及能否提供不同于旧主线的工作。通过这些条件再固定下一版费用、内容、迁移与验收；当前不把候选写成已批准的第七章，不启动新城市实现。

2026-10-26后续：已形成[三地有限联合目标候选](JOINT_GOALS_PROPOSAL.md)，补充40组正式物流子流程比较。建议按有限专题继续收敛规格，整段新目标尚未实现；新测量不改写上文21组公约对照。

同日规格收敛：两项施工未达到新增经营选择的准入条件，已缩为[三地候车回执有限尾声](THREE_CITY_EPILOGUE_SPEC.md)。固定为一次性A04档案，不新增两工程或第七章；纸面预算与实际已测物流分开记录。规格固定时本地仍为结构9/数值0.6.0；2026-10-27后续实现并发布结构10/数值0.6.1。
