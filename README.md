## 本地运行

需要 Node.js 20.19及以上的20.x、22.12及以上的22.x，或24及以上版本、npm。推荐与CI一致的Node.js 22；Vitest 4不支持Node.js 23。依赖版本固定在package.json和package-lock.json中。

```sh
npm ci
npm run dev
```

打开 **http://127.0.0.1:5173/**。服务只监听本机，端口被占用时会明确退出。浏览器需要支持 Web Locks（浏览器会话锁）；本机地址可使用，其他部署地址需要 HTTPS。

```sh
npm run typecheck   # TypeScript 类型检查
npm run test        # 引擎与存档测试
npx playwright install chromium  # 首次浏览器测试前安装测试浏览器
npm run test:e2e    # 实际浏览器流程，使用可控制时钟加速等待
npx playwright install firefox webkit  # 定向兼容检查所需的额外引擎
npm run test:compat # Firefox / WebKit关键流程；不等于真实Safari或手机
npm run build      # 类型检查并生成 dist/
npm run preview    # 在 http://127.0.0.1:4173/DistrictZero/ 查看构建产物
```

自动化测试使用隔离的浏览器环境，不会重置你日常浏览器里的游戏。开发地址与预览地址的端口不同，存档也不同；需要转移时导出再导入。

## 第一班夜工

1. 初始一人发电、一人回收。积累至少 15 零件，把一位回收工撤回后分配为维修工，安排临时路灯工程。
2. 领取“第一盏灯”的记忆，重新安排回收、积累材料，再建设宿舍。
3. 宿舍有空位时每 120 秒到达一位居民。新住客保持空闲，请主动分配岗位；首两位住客是回声居民。
4. 给站牌写上“0”，建设仓库和信箱，安排记录员。回声居民擅长整理记忆，影子居民擅长回收。
5. 信箱与累计记忆开放研究；备好材料，修复旧站台。重要选择和奖励会留在“交接事项”中等你。

工程入队时只登记计划，队首材料足够且有维修工才扣除预留费用。暂停保留工程；取消返还未完成部分的整单位费用，确认框显示实际返还与仓储溢出。运行耗电不返还，返还不增加累计取得。

照明首次选择免费，以后切换消耗 5 零件。工作供给按可调整的优先级分配；库存满或原料不足时，产出与投入同时缩减。无人维修、停电、缺料和满仓都显示具体原因。

## 旧物与新用途

1. 归档“第一盏灯”，在“住客留了话”读完装配纸条，开放标准构件。旧章末存档也从这封信开始，不自动替你选择或领奖。
2. 装配和维修共享本区维修台岗位。经营页可设置全城构件库存目标、零件与电量保留量；默认关闭，推荐备5构件、留20零件和10电量。达到目标时待命，施工用掉后继续补货；只备这一批可暂停。
3. 收音机可拆解成2构件并留下快速夹具蓝图，也可投入1构件、6零件、4记忆修复声音，得到节料台面蓝图。两条路线各有四节点、档案与街景结果；P03后可整理工具清单补学另一种蓝图。
4. 在已有工程上选择预制份数。每构件替代8零件、减少60工程点，最多6份且不超过原工程量的一半；默认普通施工，入队不扣料，开工统一预留。制作改装和补学蓝图不能预制。
5. 每区制作工具后可免费切换台面。快速夹具提高速度并增加单位耗料，节料台面降低耗料并延长加工；完整备料与施工的实测对比见[试玩记录](docs/PLAYTEST.md#v031旧物与新用途本地)。多余整份构件可拆回4零件，按返还入账。

街景可点击进入相关面板；手机底部“安排人手”“待处理”可直接定位。已完成主线默认折叠，返回报告先列实际成果，详细账本可展开。

## 从站台走进夜城

1. 归档“第一个地址”来信，测绘旧巷、登记信笺里。“夜城”页可查看地图；顶部街区按钮切换当前人手、设施与照明安排。
2. 全城共享物资、仓储和唯一工务队列。新区各有4个地块，每种设施占1块，升级不多占地。宿舍可迎来住客；也可先撤回岗位，再在地图中迁居空闲居民。
3. 供电正常的暗灯吸引影子入住，明灯吸引回声入住。2位影子、2级回收棚与暗灯形成回收专业街区；2位回声、2级信箱与明灯形成记录专业街区，各提供额外10%产出。
4. 在第0街区建设配电亭、门牌事务所。设备有效运行时逐渐磨损，状态耗尽后效果暂停；巡检共用工务队列。研究“巡检手册”后可开启自动巡检，离开期间也会按队列执行。
5. 处理共用门牌的选择，研究地址索引，编成地址簿，接通雨城。归档雨城来信后，在“夜网”页开始第三章。

V0.3.2中，地址簿要求两个新区各2居民、门牌选择与全城至少一种公共设施；接通雨城要求三个街区照明有效，再满足“有在岗及供料的一处专业街区”或“完成CM02-1与CM03-1协作委托”之一。两种证明可同时成立，P06/P07原费用与工程量保留，具体准备和实测成本见[试玩记录](docs/PLAYTEST.md#v032街巷有了生活本地)。

经营页最多保存3套岗位模板，记录当前街区的岗位、照明和全城优先级。应用时照明变化花5零件；居民、岗位或费用不足时保留全部当前安排。闲置新区设施可确认拆除后重建，建设材料不返还；住客、工作人员、未完成项目和仓储容量限制会阻止不合适的拆除。

## 街巷有了生活（V0.3.2）

1. 读完装配纸条后，在“事项”页追踪委托。接取和取消免费，交付才使用材料，每组下一阶段由你主动接取；已完成的回应和收藏可在档案回看。
2. P02后可派一位明确来源街区的空闲居民外勤。首访各有两种处理方式；后续有限线索只领一次，普通复访有已知物资回报。返程居民自动回家，结果最多保留3包，满仓会等待，不丢弃奖励。
3. 可预排最多3次普通复访，按指定地点和人手出发；同地点有未领结果会等待。召回返还未用补给，放不下的整包退款保留待领。
4. 邮递员的L02回访衔接旧巷、门牌选择和窗口投递。晾衣绳、灯罩、两扇窗与回执会反映实际履约及“共灯/姓名”选择；旧章末存档也从第一封新回访开始。
5. 经营页可制作留声匣或投递匣，每区启用一种。留声匣增产记忆并增加零件投入；投递匣在有效照明、完成巡检手册后，每秒交付一项明确勾选的委托，最多3项，不续接、不代选。保留量、预排和待领结果均可保存及离线推进。

## 让末班车每天抵达

1. 修复末班车厢，从任意街区外派一名空闲夜工至雨城。外派保留住处、占用原区人手；有列车在途或等卸货时不能召回。
2. 送去10电量、20零件；雨城每60秒将一份补给整理为12记忆，再手动发车运回。本城和外部城市各有库存，装车扣来源库存，到站才进入目的地。
3. 首次回程后选择稳班或快班，恢复长站货台。长站每60秒以12电量、8记忆回收32零件。雨城/长站标准单程分别为120/180秒，每次发车另耗4/6电量。
4. 研究运单规范配置自动合同、本城保留库存与线路优先级；研究联运调度后，共享列车从1辆增至2辆、单车运量从40增至80，可装两份标准货物。
5. 发车磨损线路；维护共用工务队列，巡检手册可解锁按线自动维护。两地各有一次真实回程，并至少启用一条有正目标、人员和线路有效、可响应需求或已达标的合同，完成时刻表与第三章终章。

**为回程留出仓储。** 新发列车会预留目的地整车空间，本地生产与领奖遵守预留。旧档迁移的未预留货物仍可能到站后整车等待、继续占车；使用库存或升级仓库腾出空间后自动卸货。停用合同保留当前运输，合同保留量也包含发车电量。

## 值得等待的列车（V0.3.3）

1. 雨城可切为“雨声封装”：每60秒用10电量、12零件生产2胶片；长站可切为“轨芯整备”：用12电量、6记忆生产2轨芯。原有常规配方仍可使用。确认切换清空当前周期，已有库存与运单保留。
2. 自动合同分别设普通/特产的本城库存目标、1–8周期补给缓冲、六资源保留量、回程包数与装载顺序。先取有需求的整包产物，否则补当前配方的原料；达标后待命，用掉后恢复。模板可快速选择“补本城原料”或“取城市特产”。
3. 同一城市回程可混装12记忆与2胶片，或32零件与2轨芯。新车出发就预留目的地整车空间，生产和领奖为它让位；预留是空位，到货才计收入。迁移的旧车保留原有满仓等待行为。保存合同与暂停独立，暂停不提交无效草稿，也不取消途中货物。
4. 候车委托和长站调查留下车辆蓝图。每套需4构件、2轨芯、20电量和120工程点；制作后手动启用，全网共用一种。强化货架增加20运量、每次发车多用2电量；护轨挂架减少25%磨损，与稳/快班组合，途中或待卸时不能换装。
5. CM04–CM06留下候车长椅、听雨间、修车棚。F05/F06分别有两种首访、一次有限线索和可选普通复访；额外材料与占用人手都有成本。站务员四封回访回应班次与真实安排，三份档案直接支付后复原，留下可阅读的来历。
6. P11现要求两地各一次真实回程，以及至少一条有正目标、人员/线路有效且能响应需求或已达标的合同；主线费用和工程量保留。胶片与轨芯用于有限内容，完成调查、委托、车辆和收藏后可收拢配置、停供或切回常规，无需每天补交。

## 历法维修（V0.5，已发布）

1. 读完L04-4后，手动确认“日期为0的维修单”，安排P13修复校时台；再阅读储时来信才开放操作。P14、P15分别需要雨城、长站的真实历法加工，P16需要实际跨轮完成；L05四封来信都不会自动确认。
2. 每600游戏秒为一轮，以校时台完工时为唯一原点。旧城记账时段为每轮第0–360秒；雨城偏移120秒，与旧城重叠第0–120秒；长站偏移360秒，重叠第240–360秒。边界左闭右开，错过窗口的单据保留到下一轮，不取消、不收费。
3. 储时默认关闭、目标120秒。每正常秒至多存1秒，支付0.20电量和0.02记忆，遵守保存的六资源保留线；目标可设0–600，实际容量在P13/P14后为300/600秒。降目标不会丢弃已有时间，暂停也不提交无效草稿。
4. 先沿原夜网把整批原料真正送到外城，再明确添加地区、普通/特产配方及“本轮起/下一轮起/隔一轮起”。排程默认暂停，初始最多1项、P15后3项，不续填。启用后每秒至多备好一项完整投入与产物空间；原料仍在当地库存，不能被普通生产挪用，取消只释放持有、不复制物资。
5. 队首在日期重叠、外派夜工仍在、模式匹配且费用齐全时，消耗60秒时间、1次校准余量，另付4电量与1记忆。指定外城执行60个原生产逻辑步，得到一批原配方产物；其他地点、列车、工务和总游戏时间不随之加速。产物留在当地，仍需真实列车运回。
6. 初始6次校准余量，剩余不超过3次时可安排“校准走失的刻度”：20零件、10电量、5记忆、1构件、120工程点，完工补3次。它共用全局工务队列、只用旧城维修工和材料，不支持预制，不刷新日期或自动启用安排。最近12次加工可回看，累计成果不会因历史裁剪消失。

本章的存档、离线等价、两设备路线与原内容回归对应K01–K12，执行证据见[验证记录](docs/VERIFICATION.md)。没有真实日期签到、每日刷新或无限循环任务；自动化通过不代表真人理解、趣味和长期平衡已经验收。

## 保存、离线与恢复

- 每 10 秒自动保存，关键操作立即保存；隐藏页面时也尝试保存。
- 在线、后台和离线共用一秒一步的引擎，保留不足一秒的余量。离开后按原安排推进，长结算分批执行。
- 返回报告分别列出生产、奖励、运行消耗、工程预留、实际返还、支线与拆回支出、发出货物、运回物资、完工、全城住客、巡检与运输次数、待处理事件和等待条件。V0.3.2还区分外勤补给预留、持有/待退补给、尚未入库的结果及实际代办数。V0.4另按旧城/分所列出库存、支援发出/收到、在途包、额度、成果与停因，封存图不计离线生产。V0.5增加实际储入/使用时间、校准、两地额外加工、在排/备料及停因，不把当地新产物算作已运回旧城。
- 设置可导出可读 JSON 文件。导入必须先检查结构、版本与状态，再确认替换；替换前保留有效恢复副本。
- 恢复副本随后续正常保存更新。需要长期保留某个街区时，请导出文件。
- 主存档损坏时尝试读取有效恢复副本；两份都无效时保留原始数据，等待有效导入或明确重置。
- 保存失败有明确提示，当前内存中的有效进度仍可导出。
- 同一浏览器、同一地址只有一页推进与写入。其他页等候；关闭主页面后，下一页自动接管、重新读档并补算。

本地存档键为 `districtzero.save.v1` 和 `districtzero.save.backup.v1`。重置只替换这两个存档，不清除其他站点数据。
